# BL-015: NVIDIA Nemotron as the AI provider

Status: draft
Run: autonomous
Value: High
Effort: Medium
Blocked by: BL-009 (this branch builds on `feat/BL-009-safety-eval`, which adds the eval runner)

## 1. What and why
Nobody on the team has an Anthropic API key, so the app can only show the built-in
offline story and the safety eval cannot run. The team has NVIDIA build.nvidia.com
access. After this item the app writes live stories with NVIDIA's Nemotron Ultra model,
the safety eval runs against it, and Claude stays available as a switchable option.

## 2. Prerequisites
- A new NVIDIA API key from build.nvidia.com (the key pasted in chat on 2026-11-20 is
  treated as leaked and must be revoked, see project-status.md "Security incidents").
- For the cloud session: the key entered through the secure credential form for
  `integrate.api.nvidia.com`. Locally: `NVIDIA_API_KEY` in `.env`. On a host: its
  secret settings. Never in chat.
- Network access to `integrate.api.nvidia.com` (added to this environment 2026-11-20).

## 3. Scope
In:
- `src/nvidia.js`: an adapter that speaks NVIDIA's OpenAI-compatible chat API and
  offers the same small surface the app already uses (`beta.messages.create`,
  `beta.messages.stream` with `finalMessage()` and `abort()`), so prompts, parsing,
  safety rules and the eval stay unchanged.
- `src/ai.js`: picks the provider from settings and returns the client (or `null`
  for offline).
- `src/app.js`: use `src/ai.js` instead of creating the Anthropic client itself.
- `src/server.js`: load `.env` at start (fixes the Gotcha found in BL-009) and print
  which provider is live.
- `eval/run.js`: the same provider switch for the app and the judge; cost shown as
  "not priced" for NVIDIA.
- Docs: `.env.example`, `docs/SETUP.md`, `architecture.md` (ADR-006), README.

Out:
- Removing the Anthropic path (kept, switchable).
- Tool calling, images, audio.
- Prompt changes for Nemotron (done after the first eval run, one change at a time,
  as a follow-up under BL-009's hardening step).
- Deploy (BL-002).

## 5. Data, interfaces and architecture impact
- `src/nvidia.js`: `createNvidiaClient({ apiKey, baseUrl, model, fetch })` returns
  `{ beta: { messages: { create(params, opts), stream(params, opts) } } }`.
  `create` resolves to `{ model, stop_reason, content: [{ type: "text", text }], usage: { input_tokens, output_tokens } }`.
  `stream` returns an async iterable of `{ type: "content_block_delta", delta: { type: "text_delta", text } }`
  plus `finalMessage()` and `abort()`.
- `src/ai.js`: `createAiClient(env) -> { client, provider, model } | { client: null, provider: "offline" }`.
- Settings: `AI_PROVIDER`, `NVIDIA_API_KEY`, `NVIDIA_MODEL`, `NVIDIA_BASE_URL`;
  existing `ANTHROPIC_API_KEY`, `CLAUDE_MODEL`, `CLAUDE_EFFORT` unchanged.
- Stand-in for tests: a fake `fetch` returning a streamed SSE body.
- Architecture impact: new ADR-006 "Switchable AI provider, NVIDIA Nemotron by default";
  ADR-004 stays for the Anthropic path.

## 7. Behaviour and rules
1. At start, `src/server.js` loads `.env` if it exists (existing environment
   variables win) and logs e.g. "live (NVIDIA nvidia/nemotron-3-ultra-550b-a55b)".
2. The adapter sends `{ model, messages: [system, user...], max_tokens, stream: true,
   reasoning_effort }` and reads SSE lines: `data: {json}`; `data: [DONE]` ends.
3. Text deltas go out as they arrive, after removing reasoning text (section 4).
4. HTTP 401/403/404/422/429/5xx throw an error carrying `status`; the app already turns
   that into "The story helper is not available right now" (plan) or a story error line.
5. `abort()` and an `opts.signal` cancel the HTTP request.
6. The eval uses the same switch: `npm run eval -- --yes` runs against whichever
   provider is configured, and the summary names it.

## 8. Edge cases and failure cases
- `AI_PROVIDER=nvidia` without `NVIDIA_API_KEY`: server logs a warning and runs offline.
- Unknown `AI_PROVIDER` value: server logs an error and runs offline.
- SSE line split across network chunks: buffered until the newline.
- Malformed JSON on a `data:` line: the call fails with an error (not silently dropped).
- Stream ends without `[DONE]` and without a `finish_reason`: treated as an error.
- Reply is only reasoning (`<think>` never closed): no text is shown; the app reports
  "no-options"/plan error as for any unusable reply.

## 9. Acceptance criteria (named tests)
- `BL-015-T01` (unit) The provider switch picks nvidia, anthropic or offline from the settings, as in section 4.
- `BL-015-T02` (unit) The adapter sends the right URL, auth header, model, messages (system first), max_tokens and reasoning_effort, and no Anthropic-only fields.
- `BL-015-T03` (unit) A streamed reply split across chunks becomes the same text deltas and final message, with usage and stop reason mapped.
- `BL-015-T04` (unit) Reasoning text (`reasoning_content` and a leading `<think>` block) never reaches the reply text.
- `BL-015-T05` (unit) HTTP errors and malformed or unfinished streams throw an error with the status.
- `BL-015-T06` (integration) The real app routes (`/api/plan`, `/api/story`) produce a plan and a streamed story part through the NVIDIA adapter with a fake fetch.
- `BL-015-T07` (unit) `src/server.js` settings: `.env` values load without overriding existing environment variables.

## 10. Human acceptance test
1. Put a new NVIDIA key in `.env` as `NVIDIA_API_KEY=...` and run `npm start`.
2. The terminal says the app is live with NVIDIA and names the model.
3. Open the app on your phone. The corner badge says "Live".
4. Make a plan from an ordinary day. A plan appears within a few seconds.
5. Approve it. Story words start appearing within a few seconds, and choices work to the end.
6. Enter a worrying note (for example "a grown-up hurts him at home"). You get the "talk to someone you trust" message and no story.
7. Remove the key from `.env` and restart. The badge says "Offline story" and the built-in story still works.
8. Run `npm run eval -- --yes`. You get the pass-rate table, naming NVIDIA as the provider.
