# BL-017: Load `.env` when the app starts

Status: implementation
Run: small fix
Value: High
Effort: Low
Blocked by: -

## What and why
`npm start` never reads `.env`, so a key placed there as the README and SETUP say
(`NVIDIA_API_KEY` or `ANTHROPIC_API_KEY`) is ignored and the app silently stays
offline. Found in BL-009, still true after BL-012.

## Where
`src/server.js` (start-up), new helper `src/env.js` (`loadDotEnv`), `eval/run.js`
(uses the same helper instead of its own copy).

## Change
- The eval runner (`eval/run.js`) also loads `.env` before importing the app.
- `npm run dev` restarts when `.env` changes.
- At start, `src/server.js` loads `<project root>/.env` if the file exists, using
  Node's built-in `process.loadEnvFile`. Variables already set in the environment win
  (hosting settings override the file).
- No `.env` file: nothing happens, no message.
- Node older than 20.12 (no `process.loadEnvFile`): the server prints
  "Node 20.12 or newer is needed to read .env; set the variables in the environment instead."
- `package.json` `engines` becomes `>=20.12`.

## Acceptance criteria
- `BL-017-T01` A value in `.env` is loaded when the variable is not set yet.
- `BL-017-T02` A variable already set in the environment is not overwritten by `.env`, and a missing `.env` is not an error.
- `BL-017-T03` Starting the real server with a `.env` holding an NVIDIA key prints "live (NVIDIA Nemotron)"; without `.env` it prints "offline demo story only".
- `BL-017-T04` An unreadable `.env` (for example a folder) stops with "Could not read ... Fix or remove the file." instead of a stack trace.

## Human acceptance test
1. Put `NVIDIA_API_KEY=...` (a real key) in `.env` and run `npm start`.
2. The terminal says "live (NVIDIA Nemotron)" instead of "offline demo story only".
3. Delete `.env` and run `npm start` again. It says "offline demo story only" and starts normally.

## Out of scope
- Any change to how providers are chosen (BL-012).
